Files tab for the session page (#26)

Three choices to make: where the list lives, what a row looks like, and what the edge states say. The tabs are live. Everything below uses a session that touched five files.

1. Where the list lives

The page keeps its two columns: the plan on the left (300px), the agent tree on the right.

Option 1. Tabs in the Plan section, as filed. The column stays 300px.

Matches the issue. Row style B (two lines) or C fits the narrow column. One line (A) clips the folder hard.

Option 2. Same tabs, but the left column grows to 400px while Files is selected.

Longer paths stay readable. The layout shifts when you switch tabs, and the agent tree gets 100px narrower. The mockup shows the Files width.

Option 3. No tabs. Files is its own section under the Plan, both always visible.

Nothing to click, and the list is never hidden. The left column gets taller, and a long plan pushes the files down. This drops the "two tabs" wording from the issue.

2. What a row looks like

Same five files, same 300px column. Every row shows the status as a letter plus its tooltip, and both counts with signs, so colour is never the only signal.

A. One line

Densest. The folder shrinks from its left side, so the file name always survives.

B. Two lines

File name and counts on top, folder underneath. Longest paths stay legible. About 40% taller.

C. Grouped by folder

Folder headers with a subtotal. Reads like a tree, costs a header line per folder.

3. The edge states

Shown with the selected row style. The wording is the part to approve.

To choose
  1. Placement: 1, 2 or 3.
  2. Row style: A, B or C, and whether the change bar stays.
  3. Beyond the file cap: totals for every file with "listing the first 200", or totals for the listed files only.
  4. Older reporter: the plain empty message, or the empty message plus the update hint.
