Background tab (#897) Screen Theme Width

Activity

Silverbolt · orchestrator · Opus 5.5

What is proposed

  • A second tab in the Activity modal, Output | Background. The existing feed becomes the Output tab, unchanged. The count on Background is the items the reporter holds for this agent. Both tabs sit in the one modal: same size (it is the modal's own height, 760 px at most), same Refresh every select, same message box under the list in an orchestrator's modal, same footer lines. The "Output tab" and "Background" screens switch between them.
  • The list behaves as the feed does. It is oldest first and newest last, scrolls inside its box, follows the newest item, and shows "Jump to latest" when you scroll up (the "23 items" screen). When there are few items the box stays full height and the rest is empty, as the feed's box does. Below it are the same status line ("Showing the newest N of N", "updated"), the same fixed line, and the same arrangement.
  • What differs, and why: there is no "Show older". The feed's older entries are stored history. Background items and their output are held in memory only, so there is nothing older to fetch. The reporter keeps every running item and the 20 latest finished ones for this agent, and the footer says so once the list is longer than that. Say if you want a different number.
  • One agent at a time. The modal is opened for one orchestrator, subagent or fork, and Background lists only what that agent started, as the feed lists only its own activity. There is no owner line and no filter. Open a subagent's modal (the "Subagent" screen) to see its shells.
  • Rows are the feed's rows (time, shape, body, the #431 open and close). The time is when the shell started, the command is cut to one line, and under it come the state, the run time and the last output. A shell with no output for 5 minutes or more gets a warning line under its state.
  • Opening a row shows the whole command and its Output, each with Copy. Output follows its own reporter option and Admin flag, both off by default.
  • Live: state, run time, last-output age and output update on the stream while a viewer has the modal open. This page does not tick.

Admin reading someone's items

  • A command and its output are the person's own content, so an Admin's view of them shows the existing red notice (.ch-nav.ro.crit) at the top of the tab, naming the Admin. The person gets the same notice in the console and a callout in podium-reporter. The record line never holds text. See the "Admin reading" screen.
