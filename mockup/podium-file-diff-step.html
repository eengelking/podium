Back and forward in the file diff modal

Issue #630. Previous and Next buttons and the position at the lower left of the diff modal step through the changed files without closing it. Every frame below works: press the buttons. Dark and light, and a 340px width, are the buttons below.

First, middle and last file

The first file has Back dimmed, the last has Forward dimmed. The title, counts and diff change in place; the Wrap lines choice stays. The list is capped in these frames: the report holds 12 of 40 files, and the pager counts the 12.

Loading and failing

The row is there while a diff loads and when it fails, so a person can step past a file that did not load. A reply for a file the person has already left is dropped. The old diff is never left on screen: the body shows Loading as soon as the file changes.

One file, and a binary file in the list

A list of one file has both buttons dimmed and reads “Showing file 1 of 1”. A binary file opens with its usual message and stepping goes on past it.

Built from, decided, and open

Reused: the modal and its header, the diff panes, .mf and the Wrap lines switch (#623), the .foot-note text, and the footer of the Files and Plan tabs (PageNav): .pager with its “Showing …” text and nav.pg holding the ‹ and › buttons, the same size and look, both disabled at the ends. Two differences from the tab, both for you to decide below: the text counts files (“Showing file 3 of 12”) and the numbered page buttons are left out. The pager’s border and padding come off because .mf has them, and it sits at the left instead of spreading across the row. No new class, color, size or icon.

Which files: the same files, in the same order, as the Files tab, taken from the whole report, not only the page the first file was opened from. Opening the 22nd file from page 2 shows “Showing file 22 of 40”. The report can be capped by the server; the Files tab already says so (“Listing the first N of M files”), and the modal counts the files it can step through, with no extra note.

Names: as PageNav’s are “Previous page” and “Next page”, these are named for what they open: “Previous file: src/a.ts” and “Next file: src/c.ts”, with the same text as the tooltip. The “Showing file 3 of 12” text is a polite status (role="status"). A disabled end is announced as unavailable. A disabled button cannot hold focus, so when the person steps onto the first or last file, focus moves to the other button and the modal never loses it.

Keyboard: Tab to a button, Enter or Space to step; holding Enter steps quickly. No arrow-key or other shortcut is added: arrows scroll the diff and the page uses [, ] and \, so any new key would collide. Esc still closes. Focus stays on the button that was used, except at an end (above); the modal does not close and reopen. The scroll goes back to the top.

Fetching: only the file in view is requested. The next one is not fetched ahead, so the number of waiting diffs does not rise. Stepping fast drops the replies for files already left; the 429 and 504 messages still show for the file in view.

Narrow width: the pager and the switch share the first line and the note wraps onto its own line below. The buttons keep the pager’s size, as in the Files tab. Open for you: (e) the Files tab shows one numbered button per page; a list of up to 200 files would be 200 buttons, so this shows only Previous and Next. Say if you want numbers (a window of them) instead. (a) the pager at the lower left, ahead of the note, with the switch at the right; (b) no keyboard shortcuts beyond Tab and Enter; (c) a capped list gets no note in the modal, as the Files tab already says so (the issue asked for one, so say if you want it back); (d) the issue asks for buttons easy to hit, and the pager’s buttons are small (about 22px); making them bigger in the modal would be a change to the standard and needs your approval.
