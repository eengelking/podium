See every Claude Code session on one screen.

Podium shows each session's model, cost, context and branch, the agents it launched, and why anything failed. Run several sessions without clicking through every terminal.

Get started Read the user guide

Podium watches. The one thing it sends is an answer to a session that is waiting on you, and only when the Admin and the session's owner have both turned that on. It never types into a terminal.

What you see for every session

Each session appears within about two seconds of its first prompt and leaves when it ends, with no refresh.

Cost
An estimate from token counts and a price table you can change in Admin. It is never a bill.
Context
How full each context window is, and how often one blew out.
Failures
Why an agent or a tool call failed, and which session it belongs to.
Branch
The git branch or worktree each session works in, and whether it has uncommitted changes.

Start in three steps

Podium is a server and a Claude Code mod. You run both yourself.

  1. Start the server

    It builds on first use and runs on your machine.

    git clone https://github.com/eengelking/podium.git && cd podium && npm link
podiumctl start

  2. Install the reporter mod

    In Claude Code, from the eengelking marketplace.

    /plugin marketplace add eengelking/skills
/plugin install podium-reporter@eengelking-marketplace

  3. Open the console

    Start a session. It shows up at http://127.0.0.1:4317.

Running it

Running the server

How to start the Podium server, keep it running, control who can reach it, and the settings that change how it behaves.

Last updated 2026-10-22Edit this page on GitHub

This page is for whoever runs the Podium server. To set Podium up for the first time, start with the user guide. The mod that sends the data is in Reporter.

Run it with podiumctl

bin/podiumctl starts, stops and watches the server without a dev setup. It has no dependencies of its own and runs Podium in one of two modes:

  • Podman container. The default when Podman is installed.
  • Standalone. A plain Node process on the host.
podiumctl start                     # builds the image on first use, then runs it
podiumctl status                    # mode, state, health, URL, boot setting
podiumctl logs -f                   # follow the log
podiumctl enable                    # start on boot / login

Auth token

The first start generates a random token and saves it as PODIUM_TOKEN in ~/.podium/config.env. This is the admin secret. It opens the Admin section.

Tip

podiumctl token shows the admin secret at any time. podiumctl token --rotate makes a new one.

Caution

Running without a token turns Admin off. Nothing would protect it.

Note

--mode, --port and --bind are saved, so later commands reuse them.

Danger

podiumctl rm --purge --yes removes the container, its data volume and the image. The database goes with it.

What this mockup shows

  • Callouts. Four kinds, each with a color, an icon and a word: Note (blue), Tip (green), Caution (amber), Danger (red). They use the app's status colors, --good, --warn and --crit, for the same meaning there: fine, watch out, will hurt. Caution's label stays in ink, since the amber is too light for text on the light theme.
  • Color. One accent, the console's blue (--sonnet), marks what is selected and what you can click: the current top-bar link, the current sidebar page, the current heading in the table of contents, links, and the selected search result. Sections alternate between two surfaces and each heading carries an accent bar. This borrows a model color for a non-model job, so it needs your approval and a Standards: line before it ships.
  • Homepage. One pitch, the real console screenshot, four things you see for every session, three steps to start, three places to go next. One primary button. The commands are the ones in the README and the user guide.
  • Docs page. Groups in the sidebar (getting started, running it, reference, project internals), a table of contents on the right, last-updated date, an edit link, previous and next. The text is the opening of docs/SERVER.md.
  • Version menu. The latest version is the default and is named in the button. The versions and dates shown are examples, since the first version listed will be the first release that ships the site.
  • Older version. A bar above the page says which version it is and links to the same page in the latest.
  • Changelog. The top-bar link opens the GitHub release page for the version being read (the newest patch tag of that line), in a new tab. The 1.4 link here is an example.
  • Search. Opens from the button or the / key, groups results by page, and searches the version being read. The terms are marked by weight and underline, not color alone.
  • Not shown. The 404 page, the standards pages (served as they are, in their own style) and the footer on narrow widths beyond what is here.
