Copy fork command

Beside “Resume” on the orchestrator page, a second quiet cell, “Fork”, copies cd <cwd> && claude --resume <id> --fork-session. Fork starts a new session with a copy of the conversation and leaves the original alone, so a stuck agent can be questioned without changing the session being investigated. Podium only copies the command; the person runs it. Nothing new is reported, stored or logged.

Where it sits

The facts bar is a four-column grid with eight cells today, so a ninth would leave an orphan. Moving the session id out of the header line and into the grid makes ten cells, which fill two rows of five, so the columns and rows stay aligned. Row one: Agents, Est. cost, Tokens, Running for, Agent time. Row two: Blowouts, Reporter, Session, Resume, Fork. The three copy controls sit together at the end of the row, and the header line keeps only the working directory. The session id is still click to copy: it reads “Copied” for 1.6 s.

Option A, in the states that matter

Idle

Label “Fork” over “Command” with the copy icon, the same shape as Resume. The accessible name is “Copy fork command”. No note opens on click.

On hover or keyboard focus: the popup

The popup opens above the cell and says what a fork does and does not do. It appears on hover and on keyboard focus, closes on Escape, and has no controls inside, so it cannot be clicked into. The cell points to it with aria-describedby. The specimen below is held open; hover the Fork cell in any other specimen to see it live.

The same popup on Resume

Resume gets one too, built the same way, so the two copy controls explain themselves alike. It says Resume continues this same session, that it should be run once the session has ended, and points to Fork for trying something without changing it. The warning about running it while the session is still open elsewhere is from my reading of how Claude Code behaves; I will check it against a live session before the wording is final.

After a click

Resume and Fork both read “Copied” with a check for 1.6 s, and nothing else opens. If the browser refuses the clipboard, nothing changes and the cell stays as it was; there is no fallback field.

Ended and waiting sessions

Identical to a running session. Fork is offered for any session whose transcript exists.

Narrow window (400 px)

At or below 640 px the facts bar is two columns and five rows, so Resume and Fork share the last row and the popup is as wide as the card allows.

Not on History

History’s page is read-only, so Fork is not offered there, the same as Resume is not. Say so if you want it.

To settle before code

  1. Popup wording. Shown in the popup: “The original session is not changed.” / “Permissions you allowed for the session are not carried over. Approve them again in the fork.” / “It works in the same directory, so file edits are real. Start it in a worktree to keep them apart.” / “Flags such as --mcp-config, --settings, --plugin-dir and --add-dir are not restored. Pass them again if the session used them.”
  2. Popup on hover. Settled: a hover and focus popup, no note on click. Touch screens have no hover, so a tap copies and the popup shows while the cell has focus. The real card clips its contents (overflow: hidden), so the popup has to be drawn outside the card or the card’s clipping relaxed. I will decide that in the code.
  3. Worktree variant. Recommended: not offered. claude --help lists -w, --worktree and --fork-session separately, but nothing says they combine with --resume, and I have not run it. I will test it against a live session during the real-session check and only add a second command if it works. The popup’s worktree line then stays as advice.
  4. Transcript gone. Settled: no such state. Podium cannot tell without a new report field, so the command is always offered and the popup names the 30-day limit.
  5. Mid-turn forks. Offered the same as between turns. The docs do not say what a mid-turn fork contains; I will record what I see in the issue.
