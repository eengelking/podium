What this mockup proposes

  • Where the figures go. #722 says "Usage or Reporting sessions, whichever already holds the neighbouring figures". Sessions already holds duration and agents per session, so length, waiting and agent types go there as three new sections. Usage already holds "most live at once", so sessions per person per day and busiest hours go there. No new page and no new menu entry.
  • Same shape as the other reports. Period and filters (with the Harness filter #1031 asks for), the "based on" line, summary figures, one neutral-ink chart, the table, the pager, and CSV, JSON and Print. Both pages' exports carry a harness column for every row.
  • Length and waiting by week shows how long sessions ran and how much of that was spent waiting on a person. The chart is the new figure (hours waiting per week); the table holds the rest and a footer row for each harness. Waiting is a question, a plan or a tool's permission, never a wait for background work or a timer.
  • What sessions waited for splits the same waiting three ways (permission, question, plan) and adds up to the figure above it.
  • Agents launched counts by agent type with a column for each harness, and How deep agent chains go counts them by how many levels down they sit. Both harnesses report which agent launched an agent (an agent the session launched itself has no parent, in plugin/opencode/report.ts as in Claude Code), so depth covers every harness and there is no gap to state. (An earlier version of this mockup said OpenCode did not report it; that was wrong.)
  • Sessions per person per day gives each person's active days, sessions, sessions per active day and busiest day. The Total row counts everyone in the filter, as the Spend table does.
  • Busiest hours is the highest number of sessions live at once in each of the 24 hours, as a chart and, with Show as, a table. A chart has a table view, as on Spend.
  • The state toggle shows the new gap: waiting time is recorded only from the upgrade, so earlier weeks show a dash and the totals say which weeks they cover, instead of drawing zeros. The existing "Podium has no history before ..." line is unchanged and not redrawn.

What it needs underneath (not drawn)

  • Today's daily summaries hold session count, total and longest duration and agents per session. They hold no waiting time, no agent type or depth, and no per-hour peak, and the per-second samples last 24 hours. So the build adds summary rows for waiting (by reason), agents (by type and depth, per harness) and the peak per hour, in every storage adapter in the same PR, with the retention the other summaries have (395 days). Only counts, durations and names are stored: never a question's text, a plan, a tool's input or a path.
  • Waiting time comes from the status a session already reports (waiting, with a reason), which both harnesses send, so no reporter change is needed. A session idle at the prompt is reported as waiting too (reason input, no note) and is not counted: only a tool's permission, a question and a plan approval are. Plan and question approvals arrive as a permission dialog on Claude Code, told apart by the tool's name.
  • #721 is built in parallel and changes the Tools page and the reporter protocol. This page touches neither.

Where the build differs from what was drawn

  • Durations use the app's own format (51:30 under an hour, 8h 48m to a day, 1d 09h after), as the Average duration column on this page already does, not 51m.
  • Each new table has its own CSV and JSON in its section's title line, as the Spend projection does (no Print), so every new figure can be exported. The page's own buttons still download the report the page had.
  • The Harness filter narrows the new sections. The older report on each page (sessions by outcome, usage by week) is not kept per harness, so it is not sent the filter and the page says it covers every harness. A Person, Group or Model filter on Sessions holds the new sections back with a line that says why, because they are not kept by those.
  • The first column of a period table is not marked "(so far)" for the current period: no other report table in the app does that.

Not new

  • Every class on the page exists already (.sum, .chart, .ptab, .seg, .apager, .note-line). The two bar charts use the same ink bars as Tools. No color, component or pattern is added, so no standards fragment is needed.
