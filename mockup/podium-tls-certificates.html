Keys and certificates are stored in /data/tls (keys mode 0600). Keep that folder on a volume or host folder that survives a rebuild: without the CA key, every reporter config must be reissued.

Renewal and lifetimes

The serving certificate renews itself by default and keeps the one it replaced as a backup. Reporters renew their own certificates. A change saves when you leave the field or flip the switch, and is written to the Admin log.

Renew the serving certificate automatically

Rotate the certificate authority

Creates a new CA. Reporters keep working through an overlap while they pick up the new CA when they renew. You retire the old CA when none are left.

Rotate the certificate authority?

Podium creates a new CA and serves a certificate that chains to both, so reporters that still hold the old CA keep working until 2026-11-19 (30 days). Each reporter picks up the new CA when it renews. A reporter that has not renewed by then needs its reporter config reissued from Admin > People.

End the overlap now if the old CA key was exposed. Every reporter then needs a new reporter config, and open connections are closed.

What this mockup proposes

  
    
    
  • The header pill. It sits with the other status pills, after the connection pill. It watches the Podium CA and the serving certificate, whichever expires first, and never a person's certificate. It shows nothing until 30 days are left, unless a renewal has failed, when it shows at once. It is a link: click it and Admin > Server > Certificates opens.
    • 
    
  • Four stages, each a shape, a word and a color. 30 days or fewer is blue with a clock and "Certificate expires in 28 days". 10 or fewer is orange with a triangle and the same words. 5 or fewer is red with the same triangle. Expired is red with a ring and a cross and "Certificate expired". Orange and red share the triangle and are told apart by color and the day count, which the maintainer approved. The tooltip names the date.
    • 
    
  • It is a status, not a notice. The wall-notice rules are for information. A certificate that is about to expire or has expired is a condition the Admin has to act on, like the "reporters need an update" pills, so it stays in the header and has no X. The Admin can switch the healthy countdown off when they rely on automatic renewal. A failed renewal and an expired certificate always show, so the switch can never hide a problem.
    • 
    
  • The Certificates page is built from the Admin page parts: the status table, the settings box with the on/off switch rows and the number rows, a box for the two actions, and the warning-bordered confirmation. A number saves when the field is left and shows a rejected value in place (leave a lifetime field with a value outside its range to see it); a switch flips at once. It sits in the Server group, beside Security.
    • 
    
  • Automatic renewal is the default. The serving certificate renews itself, keeps the one it replaced as a backup, and swaps in with no restart. The pill appears for it when a renewal fails, with the reason in the critical color and what to try.
    • 
    
  • The alert is a band row, the same row the orchestrator page uses: a tinted full-width row with an icon, a bold line and a detail line. It is blue at 30 days (the existing blue band), orange at 10 (the existing orange band) and red at 5 and when expired (a new red band). It sits at the top of the Status panel. The app has no red band today, so .band.crit is a proposal.
    • 
    
  • The expired states. A serving certificate that expired needs one action, Renew now, and nobody else has to do anything because reporters trust the CA. An expired CA is the worst case: the page lists three steps (rotate the CA, reissue each bundle on People, each person replaces theirs). The Admin signs in with their name and token, over the loopback address or past the browser's warning. The recovery button becomes the one primary button on the page.
    • 
    
  • The serving certificate's names can be a long list, so the row shows the first name and "and 5 more" as a link: click it and the app's small modal opens. The modal lists the names under the place each one comes from (always included, PODIUM_ALLOWED_HOSTS, the bind address), marks each as a name or an address, wraps a long name inside its row, and offers Copy names.
    • 
    
  • People is the real page with its columns reworked. The two credentials are now two cells, Reporter certificate and Console token, each with its own status badge (the certificate's badge has the app's tooltip with the date and what happens next). The old Status column is gone because each badge now says it, and the token's id (pdm_<key id>) is in the tooltip of its badge. The Group select sits under the person's name and "created" under Last report, so the table loses a column and fits the page. All the actions are in one Actions menu per row, grouped as Console token, Reporter certificate and Person; an action that does not apply is disabled. Choosing a revoke, a rotate or a reissue opens the warning-bordered confirmation in a full-width row under the person, so the text has room. Delete opens the app's existing dialog.
    • 
    
  • After Create user (the third Screen button, or press Create user) the page shows the app's show-once box with two parts. The token is for the console sign-in. The reporter config is one file, reporter-config-<name>-<epoch>.pem, that holds everything the reporter needs: the server address, the CA, the name, and the certificate with its private key. The only step is to save it in ~/.podium/ on the machine where Claude Code runs; every new Claude Code session there uses it and podium-reporter finds it. A person who keeps it elsewhere sets PODIUM_REPORTER_CONFIG to its path. Nothing is installed on the machine, as with a kubeconfig. A session that is already running does not pick the file up, so the person starts a new one, and podium-reporter needs Node.js on the machine's PATH. Podium keeps only the certificate, so the file cannot be downloaded again: Reissue config makes a new certificate and key and shows the box once more. An Admin can download any person's public certificate from their row. The Certificates page keeps the CA with its fingerprint and a Download CA button, for installing it in a browser.
    • 
    
  • Reporters over HTTP is a switch under the renewal settings. While it is on, a warning-colored line says it is not encrypted, that anyone on the network can read and change the name, the token and what the reporter sends, and when it is acceptable. Turning it on is immediate. Turning it off asks first in the warning-bordered box, names how many reporters it will refuse, and says the loopback console keeps working.
    • 
    
  • Storage. The note under the status table says where keys live and that they must survive a rebuild.

Open decisions, with a recommendation

  

    
DecisionRecommendationWhyStatus

    
      
1. Pill and badge colorsAdd .pill.soon, .pill.serious, .badge.soon, .badge.serious, .badge.bad, from existing tokens.The app has yellow (warn) and red pills but no blue or orange. In the Solarized theme the blue stage's token is teal, so the first stage will not read as blue there.Approved

      
2. Orange and red share a shapeKeep the triangle for both, told apart by color and the day count.A third icon is a new shape to design. The standards want a shape per state, so this is an exception.Approved

      
3. Not a wall notice, and the switchA header status with no X. The switch is an Admin on/off switch that hides only the healthy countdown.A failing or expired certificate is an error and cannot be closed.Approved

      
4. The thresholds30, 10 and 5 days, fixed.As the maintainer set them. They could become settings later.Approved

      
5. Grace after a reporter certificate expires30 days, a setting.A reporter renews itself with a signed request. An expired certificate cannot, so a short grace keeps laptops that sat idle from needing an Admin.Approved

      
6. Lifetime boundsServing 30 to 825 days, default 365. Reporter 30 to 365, default 90. CA 10 years, fixed at creation.The issue asks for a default, a minimum and a maximum. 825 days is the longest lifetime most browsers accept for a private CA's certificates.Approved

      
7. BackupsKeep the last 3 replaced serving certificates in /data/tls/previous.The maintainer asked for a backup of the certificate it rotated from. Three covers a bad renewal without growing without bound.Approved

      
8. Recovery when the CA expiredSign in with name and token past the browser warning, or on loopback.Plain HTTP on loopback stays available, and the Administrators group always keeps a member, so an Admin can always recover.Approved

      
9. A pill that is a linkAdd it, as a plain link whose text carries the meaning.The app's status pills are plain spans today.Approved

      
10. Where the pill sitsAfter the connection pill, with the "need an update" pills.A comment in TopBar.tsx says to leave the space right of the connection pill empty, and the update pills already sit there.Approved

      
11. Revoke wordingKeep Revoke (token). Add Revoke certificate, Revoke all (token and certificate), and Reissue config.One name per action. Revoke all is the "disable the person" idea in a word the page already uses.Approved

      
12. A failed renewal always shows the pillThe switch hides only the healthy countdown. A failed renewal and an expired certificate always show.A switch must not be able to hide an error that cannot be closed.Approved

      
13. Ending the CA overlapA second critical button in the confirmation, with its reason as a hint line.No standard puts a checkbox inside a confirmation.Approved

      
14. The alert is a band row, with a new red stateUse the band row for the certificate alert, with .band.crit for red.The alert should look like the orchestrator page's band. The app has blue, orange, green, yellow and grey bands but no red.Approved

      
15. Status text in a tooltipUse the app's Tip on the People status badges; the date and the token id live in the tooltip, not the row. The Certificates page keeps its dates in the table. The header pill's date is a plain title, and the same date is on the Certificates page.Keeps the People row short, and the tooltip opens on keyboard focus too. A plain title does not open on focus, so nothing the pill says is only in the title.Approved

      
16. One actions menu per rowGroup the row's actions in one menu (Console token, Reporter certificate, Person) and confirm in a full-width row under the person.Seven actions do not fit beside the other columns. The alternative is the selection bar the page already has, with the actions moved there.Approved

      
17. What an Admin can download laterThe public certificate and CA from the row. The private key only at creation or reissue, shown once.Podium keeps only the certificate, so an Admin or a stolen database never holds a person's key.Approved

      
18. The names link and its modalThe text "localhost and 5 more" is the link. The modal groups names by where they come from.The list can be long, and a person wants to know why a name is on it.Approved

      
19. Status folded into the credential cellsDrop the Status column; show each credential's status in its own cell.The page had one status (the token's). With a second credential, one Status column is ambiguous, and two badges beside their credentials say it more clearly.Approved

      
20. The reporter makes its own TLS connectionThe reporter ships a small helper, started for the session, that reads the one config file and makes the HTTPS connection with the CA and the client certificate from it. The reporter sends its requests to the helper over a local socket. The server authenticates the person from the certificate in the handshake. Ask the engine team for a CA and certificate option on $.http.fetch, which removes the helper.Measured on Claude Code 2.1.305 (macOS): 20 of 20 requests, about 2 ms each, with the server seeing the person's certificate on every handshake, and the CA only in the file. It needs node on the person's machine (measured: without it the spawn fails), and the engine types say $.process is CLI only; the desktop app and VS Code are untested.Approved

      
21. One file, no separate CA fileThe CA is inside the reporter config, so there is no ca.pem, no NODE_EXTRA_CA_CERTS line and no restart.This follows from decision 20. The earlier two-file flow (a stable ca.pem and a settings line) is the fallback if the helper is not accepted.Approved

      
22. The token's id in a tooltipShow the token as pdm_<key id> in the tooltip on the active or revoked badge, not in the cell.The key id only finds a person and is not a secret. The tooltip frees the column's width.Approved

      
23. Reporters over HTTPA switch on the Certificates page, with a warning line while it is on. On for an existing install, so nothing stops when TLS is turned on. Turning it off asks first and says how many reporters it refuses.The issue asks that HTTP keeps working during a move and never falls back unasked. The Admin ends it when everyone has moved. The console on loopback stays on HTTP, so an Admin can always recover.Approved

      
24. Where the reporter config livesKeep ~/.podium/ as specified. When several reporter-config-*.pem files are there, the newest by an issued-at line in its header wins and the reporter ignores the rest.~/.podium/ is also podiumctl's home (config.env with the admin secret, data/, podium.log). A reissue leaves older files beside the new one, and the old one is revoked.Approved

      
25. A new CA delivered in the renewal responseOnly for planned rotation, as an addition, with a cross certificate that verifies under the old CA. After an emergency rotation the server does not offer it: a hard cutover and a reissue, which is "Rotate CA and end the overlap now".The channel is authenticated, but a leaked old CA key would let an attacker hand out their own "new CA".Approved

      
26. CA rotation in progress, and Retire old CAA blue band says it is in progress, a Previous certificate authority row shows how many reporters still use it, and Retire old CA… asks first and names how many it will refuse.The overlap needs an end the Admin can see and choose. Retiring also closes open connections, which do not drop by themselves.New

      
27. The show-once box differs from today'sThe heading is "Token and reporter config for X", "Copy settings" becomes "Copy token settings", and the box has no primary button.It now holds two things, the token and the file. Create user stays the page's one primary button.New
