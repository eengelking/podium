Which harness runs a session, and what it does not report

Podium now stores the harness of each session (#851). This design shows it on the card and the pages, names the model without Claude-only wording, hides what a harness does not report, and makes the tool name, the short id and the resume command work for any harness. Claude Code sessions look and behave as before.

1. The harness badge

One chip, a shape and the harness name, in the card's model group before the model chip. It shows on a card and in the page header only when the wall holds sessions from more than one harness, so a Claude-Code-only wall is unchanged. A harness Podium has no entry for shows its id with the plain square.

2. A neutral model label

The chip shows the label the reporter sent (modelLabel) when there is one, else the family name as now for Claude models, else the raw model name. The title carries the full model id and its provider. "(not a Claude model)" goes away. A model Podium cannot price shows the harness's own figure when it reported one, marked "from OpenCode", and "n/a" with the reason only when it reported none. Voice: a cost Podium works out is an estimate and says so; one the harness reported does not need to.

3. Fields a harness does not report are hidden, not zero

When the harness says it cannot send a field, the cell for it is absent, and the footer is three cells wide. A session that can send a field but has not yet shows what it shows today (—). The reason is said once, on the page (the orchestrator page's header), not on each card.

4. Tool names, short ids and the resume command

Tool names. The UI maps per harness, in frontend/, keyed by the harness id: the shell tool is Bash for Claude Code and shell for OpenCode, and both render as the same command row. The reporters keep sending the tool's own name. The "(Recommended)" tag is stripped only for Claude Code.

Short ids. Today the first 8 characters, which leaves 4 informative ones on ses_…. Proposed: the first 8 characters after a known prefix, with the prefix kept, so two OpenCode sessions never collapse to ses_a1b2.

Standards

Tokens only. The cards are the app's own (card sc, z1 to z3, .band). It adds one component, the harness badge (chip hx), plus a source word under a reported cost and a three-cell footer, so it is a standards change that needs the maintainer's approval and a Standards: line under [Unreleased]. The badge is shape plus word, never color alone. No other variant changes.
