Bash output in the activity feedactivity-output

Lets a person open a Bash row in the Activity feed to see what the command printed and how it exited. Needs the Agent activity feed on, and the reporter's activityOutput option on the machine as well. Output is held in memory while the panel is open and is never stored. Off, no output is captured or sent.

Off
Output holds whatever a command printed: file contents, environment dumps and tokens the redactor does not know. Podium hides the secrets it recognizes, but it cannot promise to catch all of them. Anyone who can open the Activity panel of a session can read its output while the panel is open.

What this adds to Admin

  • One new switch in Admin > Settings > Feature flags, Bash output in the activity feed (activity-output), off by default. It sits under Agent activity feed, which it needs. Same row, same switch, same Admin-log entry as the others (SwitchRow).
  • A caution when it is on. The warning box the Session recording flag already uses: output can hold secrets the redactor does not know, and who can read it. It shows only while the switch is on. Turn the switch on in the bar above to see it.
  • Admin > Server > Data says what history now keeps: the whole command (up to 20,000 characters, redacted) instead of the first 300, and never output. One added line; the controls are unchanged. The existing warning about more reporter traffic is not changed by this.
  • What people see when output is missing now has two reasons, each in words: the Admin has it off, or the machine has it off. The machine's text names the reporter option, activityOutput (Send a Bash command's output), the way the feed already names activityFeed. An older reporter says it sends no output.
  • No new Admin page, table or setting beyond the switch. The Stored activity page lists sessions, not entries, so it has no rows to open.
  • Everything here is an existing piece: .srow, .sw, .warnbar, .note-line, .feedoff. The flag's id, name and description are proposed and live in server/src/fleet/featureFlags.ts. The reporter option name is proposed and lives in the mod's plugin.json.
