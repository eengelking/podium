Wrap lines switch in the file diff modal

Issue #623, on top of #319. A switch in a new bottom row of the diff modal wraps or unwraps long lines. Wrapped is the default and the choice is kept in the browser. Every frame below has a working switch; flip it to see the other state. Dark and light, and a 340px width, are the buttons below.

Side by side, with the foot note

The wrapped default. The changed long line at the bottom breaks at the pane edge on both sides; its continuation sits under its own text, not under the line number, and the number and the − or + sit once, on the first visual line. The old and new halves stay level because they share one grid row. The note is at the left of the bottom row and the switch is at the right. Switched off, the panes are as they are today and scroll sideways.

Side by side, without a note

No truncation and nothing redacted, so there is no note. The row is still there, so the modal does not jump between diffs, and the switch is at the right.

Below 720px: one column

The unified view wraps the same way: both numbers and the mark on the first visual line, the continuation under its own text. At this width the note and the switch stack, note first, the switch still at the right.

What is new, what is reused, how it is built

Reused: the modal, its header, the panes, the line rows and colors, the hunk bars, the redaction marks and the .foot-note text. The switch is the .sw component: a role="switch" button with aria-checked, named by “Wrap lines” and by its state word (On or Off) through aria-labelledby, as in Admin > Settings. The state is the word as well as the knob position and the green.

New: (1) .mf, the modal’s bottom row, holding the note and the switch; the note’s border moves up onto it. (2) .sw is written under .adminv in admin.css, and the modal is rendered outside that, so the rules need to apply anywhere. That moves the existing rules out of the Admin scope with no change to how they look in Admin, . The knob is the same white as in Admin (the mockup draws it with --on-good, which is white in the default theme). A switch used outside Admin is recorded as a Standards: line. (3) The wrapped layout. The two panes stay two elements in the same order, so Tab and screen reader order are as today, but each line is placed on one shared grid by its pair number, so the halves of a row are always the same height. A very long line is one grid cell with overflow-wrap: anywhere, so a minified file wraps at the pane edge without widening anything.

Open for you: (a) the label “Wrap lines” and the placement at the lower right as the issue says; (b) whether to keep the choice for unified and side by side as one setting (this mockup does); (c) the 340px unified frame stacks the note above the switch rather than shrinking the note.
