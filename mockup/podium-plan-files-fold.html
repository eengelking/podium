Orchestrator page: fold the Plan / Files column

Issue #604. A control on the left column folds the Plan / Files panel away so the Agents section takes the full width of the work area. The choice is saved per browser and applies to every orchestrator's page.

Open and folded (wide)

Open: a 16 x 32 px vertical pill sits on the column's right edge, chevron pointing left, tip "Hide plan and files". Folded: the column shrinks to a 28 px rail with the pill and the name "Plan and files" set sideways; the pill points right, tip "Show plan and files". The rail is the visible, screen-reader-reachable way back. The Agents table gets the width, so its columns are not squeezed.

Files tab selected (400 px column)

The column keeps growing on the Files tab, as today. Fold it, then show it again, and the Files tab, its scroll position and the plan's page come back, because the panel is hidden, not unmounted.

Narrow (400 px, stacked)

The control still works and hides the panel in the stack, so Agents moves up. Open: the pill straddles the bottom edge of the panel, turned to point up. Folded: a 16 px bar across the width with a down chevron, the same shape the Board's KPI bar has when it is folded.
ComponentNew: .fold-tab with .fold-col and .fold-rail, built on .tbar-tab / .kpi-tab (same size, border, hover, focus ring and tip, turned 90 degrees). Added to the standards in the release-prep PR, not this one. Nothing existing fits a side column exactly.
NarrowThe control hides the panel in the stack rather than doing nothing. Why: stacked, the plan sits above the Agents table and pushes it a screen down, so folding is more useful there than at full width. The saved flag is the same one at every width.
Links into the panelNone exist today. Nothing on the page (header, facts, status band, waiting items, notices) links or scrolls to the Plan or Files panel; I read FocusView, FocusHeader, FactsBar and StatusBand. So the build has no link to reopen the panel for. If a later feature adds one, it must open the panel first.
AccessibilityA real button with aria-expanded, aria-controls naming the panel, a name that says what it will do ("Hide plan and files" / "Show plan and files"), a visible focus ring, tip on hover and focus. While folded the panel is display: none so a screen reader does not read it, and the rail's name tells it where the panel went. Focus stays on the button when it is pressed.
PersistenceOne localStorage key, podium.planFiles.collapsed, read with readJson. Default: open. Not tied to the Fleet page's panes, wall mode or a session.
ShortcutNone proposed. Say if you want one.
