What this mockup proposes

  • Three sections added to the Tools page #720 built, after Calls by tool: Tool failures, Permission prompts and Call duration. They share the page's period, grouping and Harness filter, its "based on" line, and CSV / JSON / Print. Each carries a harness column in the exports.
  • Tool failures shows failures and calls side by side with the rate, sorted by failures so the tool that fails most is first. The bar chart is the app's existing horizontal bar list. An MCP server opens to its tools, as in Calls by tool.
  • History link. A row opens the failures still stored in History (30 days), with the count it opens. Older failures say "Older than 30 days" and a person without access to the session sees "Counts only" and no link, the same rule as the Failures page. Use the History link buttons above to see each state.
  • Permission prompts has Asked, its share of the tool's calls, then Allowed, Denied and No answer, which add up to Asked. "Answered in Podium" is a count within Allowed and Denied, not a fourth outcome.
  • Call duration is a median and a 95th percentile per tool. It says plainly that only Claude Code supplies times and that OpenCode's calls are left out.
  • Nothing new in the design system: the table, summary figures, bar list, rowbtn, .mtool sub-row, note line and pager all exist from #720 and #484. The three History states are plain text and a link.

To confirm before code

  • Duration. The Claude Code reporter wraps each tool call, so it can time it, but sends only counts today. Whether OpenCode can time a call is unchecked, so the mockup shows it as a gap. Whether a call that waited on a permission prompt includes the wait also needs deciding.
  • Permission prompts are not stored per tool at all today, and failures are stored without a harness. Both need a daily rollup change in every storage adapter, and a reporter change in every harness.
  • The figures here are invented and add up (411 failures, 1,256 asks, 18,202 timed calls).
