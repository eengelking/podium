What this mockup proposes

  • No new page and no new menu entry. Each figure goes where its neighbours already are: cost on Tools (the tool counts are there), tokens and cache on Spend (which already shows tokens in and out), model, effort and context on Sessions (which already holds outcome, model, effort and blow-outs). Every added section uses the existing classes (.sum, .chart, .ptab, .seg, .note-line), so no color, component or pattern is new and no standards fragment is needed.
  • Same shape as the other reports. Period and filters with the Harness filter (#1031), the "based on" line, summary figures, a neutral-ink chart, the table, and CSV, JSON and Print. Every export carries a harness column, and a figure one harness cannot supply shows a dash with the reason in its tooltip and a line under the table.
  • Cost per call and per session is a model's priced spend over its tool calls and sessions. A model without a price shows a dash and stays out of the totals, as everywhere else.
  • Decision for the maintainer: cost "by tool". The issue asks where cost goes "by tool and model". Podium has the tokens of a session and the calls it made, but not the tokens each call used, so a tool's own cost cannot be measured and splitting spend over calls would invent it. This mockup draws two honest figures instead: cost per call by model, and the average spend of the sessions that used each tool, labelled as what it is. If you want a true per-tool cost, the reporters would have to send tokens per call, which is a larger change and touches every harness.
  • Tokens and cache hit rate gives the four token counts per week, the rate as a chart and a column, and a row for each harness.
  • Model and effort mix shows the share of sessions per model or per effort each week, switched by Mix of. It is shares and counts only.
  • Context fullness buckets sessions by how full the window was at the end, with how many sessions compacted on their own or continued after /clear.

What it needs underneath (not drawn)

  • Tokens (in, out, cache read, cache write) and cost are already in the usage rollup, and model, effort and the highest context percent are in the sessions rollup. New: the context percent at the end as a bucket, a count of /compact and /clear per session, and tool calls joined to cost. These add summary rows in every storage adapter in the same PR, kept 395 days like the others. Only counts and names are stored.
  • #721 is merged, and this adds to the Tools page it changed. Where a harness reports no effort, the Effort mix shows its sessions as Not reported (stated on the page).

Open questions

  • Resolved in the build: the two honest figures (cost per call by model, and the average spend of sessions that used each tool). Per tool cost is not drawn.
  • Resolved in the build: /clear is counted from the session that continues after it (Podium already stores which session it continues), so no reporter change is needed. Only automatic compactions are counted, because those are the compact events Podium keeps; a /compact you ran yourself is not.
