An Admin responds only when the owner allows it (#1251) Mode Width

1. What changes

Today any Admin can send to any person's session, run /clear or /compact on it, or answer its question, plan or tool prompt. The owner is not asked and sees only a terminal line. Chat already asks the owner before another person's message reaches their agent (#1034). This brings an Admin under the same rule: the owner allows it, for each of their reporters, and it is off by default. An Admin can still read, pause and remove as before, and the owner is told of each.

Where the switch lives: the owner already sets what others may do with their reporters on My reporters. The allow is kept for a reporter (a machine), so it is a column of the table of the owner's reporters there, not in the Activity window, which an owner opens only after something is already blocked.

2. Proposed: one more column in Your reporters on My reporters

The table is the page's own, unchanged, with one column added between Last report and Live orchestrators: Admin may respond, a switch in each row, off by default. The allow is kept for a machine, which is what a row is. The page confirms a change in the toast it already uses ("Admin may respond on Eds-MacBook-Pro-14: On."). A save that fails puts the switch back and says so in words under the table, as the page shows other errors.

3. Proposed: what Root sees on Ed's session without the allow

The card's band does not change: Respond stays live, because the Respond window is also how an Admin reads someone's waiting question, plan or tool prompt (#1073), and the owner is told of that read as today. What changes is inside the window. The ask is shown in full, read-only, and the answer buttons and the message box give way to one note that says why and what Ed can do. A session owned by Admin or by no one, and an Admin's own sessions, are unchanged: an Admin responds to those without any allow. With the allow, the window is as it is today.
