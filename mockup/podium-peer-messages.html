1. Admin > Settings

One feature flag turns the whole feature on or off for the server, off by default. When it is off, the tools are not offered to sessions, My reporters hides its messaging sections, and Traffic leaves the top bar. The limits sit in their own section once the flag is on.

2. In the sending session

podium-reporter gives an orchestrator three tools. podium_peers lists the orchestrators it can see, podium_send sends one a message, and podium_request_access asks its person for a right it lacks. Each answer says what happened in plain words, for the model and for the person reading the transcript.

3. Approving a message

On a link that needs approval, a message waits for its owner. It shows in My reporters under Waiting for you, and in Ed's sessions on the receiving machine. Answering in one place closes the other. The receiving orchestrator's card does not get the amber band, because that session is working, not waiting on its person.

4. In the receiving session

A message arrives as a new turn once the session's turn has ended, never in the middle of one. Claude Code frames it as a podium-reporter message, and the text adds who sent it and what it cannot do. It is never sent as the person's own words.

What this mockup assumes

  • Only one person's own reporters can be linked. The server refuses a link between two owners, whatever the settings say.
  • Three switches, all off by default: the Admin's flag, the peers option in each machine's podium-reporter, and a right on My reporters. Trust my own reporters turns the last one on for every pair at once.
  • A message reaches the receiving orchestrator only when its turn has ended. Agents it launched never receive one, and only an orchestrator can send.
  • A message never answers an open question, plan or permission prompt, and never runs /clear or /compact.
  • Every message is written to the Admin log with sender, receiver, owner and kind, never its text. Its text is kept on the server for 30 days, readable by its owner and an Admin.
