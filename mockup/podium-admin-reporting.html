What this mockup proposes

  • A new menu group, Reporting, with six pages: Usage, Spend, People and groups, Sessions, Failures, Admin activity. (This mockup also drew a seventh, Data kept; #432 moved it to Admin > Server > Data, see mockup/podium-activity-history.html.) Spend moves here from Activity, which keeps only the Admin log.
  • The old Reporting and security page is renamed Security (content unchanged), so there is one "Reporting".
  • Every report has the same shape: Period and filters, then the report with totals, a neutral-ink chart, the table, the pager, and CSV / JSON / Print.
  • A line under the filters states the time zone, what the figures are based on, and how far back the data goes. A period before the first rollup says so instead of drawing zeros.
  • Spend has three sections. Spend today keeps its content, but a person's row is now a button that opens a breakdown (#482): by session, by model, and orchestrator against agents, each adding up to the row. A model without a price shows a dash and is counted in a line under the breakdown. On "by group", a group row opens its people first.
  • Projection (#483): a straight run rate over a trailing window (7, 14 or 30 days) projected to month end or 30 days ahead, with the window, the method and the assumptions beside the number. With too little history it says "Not enough history" instead of a number.
  • Spend over time is the period report from before. A session counts on the day it was last seen.
  • The Failures page links each class to History only for sessions still within the 30 days History keeps.
  • Data kept shows each rollup table, its oldest day and its retention (395 days), next to the shorter detail retention. Consistent with #432. Since #432 it is the Data page in the Server group, with an Activity history setting.

Pages not drawn

  • People and groups, Sessions and Admin activity use the same stack and the same table and filter pieces. Their columns are in docs/spec/.
