What the footer says about the build

The footer is a stack of rows, each on its own line: the links, a Dev row, the version, and the copyright at the very bottom. A release build has no Dev row. Any other build (a commit on development, a branch, a build with local edits) adds Dev: <commit hash> above the version, so a dev build is never mistaken for a release and two dev builds are told apart. The copyright moves off the version row, which also stops that row wrapping in a narrow rail.

Where else the build shows

In Claude Code, the mod's status line gets a dev segment after the version, set off by a pipe. It shows in every connection state, so a dev build is identifiable even when it is offline or refused, and the only dot on the line is the one that says live or not. A release reporter's line is unchanged. The ⚠ is the plain-http warning and is independent of the build.

Rules shown here

  • Rows, top to bottom: Theme credits and License, Dev (dev builds only), the version, the copyright. The release footer is the same rows without Dev, and the copyright is now its own row instead of sharing the version's.
  • A release is a build whose commit is exactly a vMAJOR.MINOR.PATCH tag. Everything else is Dev, whatever the branch.
  • The hash is the 8-character short hash, set in the mono font. -dirty follows it when the build had local edits.
  • No build information (a tarball with no git, or an older server) shows the version alone. An unknown version shows the copyright alone, as today.
  • The word Dev and the hash carry the meaning. No new color, chip or icon is added, so nothing here depends on color.
  • The footer's links keep their visible focus ring and the text wraps inside the rail at every width. Nothing scrolls sideways.
