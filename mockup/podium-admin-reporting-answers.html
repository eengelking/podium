What this mockup proposes

  • Where the figures go. #725 does not name a page. #722 put "what sessions waited for" on Admin > Reporting > Sessions, and this issue is the other half of the same story (what people did about it), so both new sections go on Sessions, after the waiting sections drawn in mockup/podium-admin-reporting-session-time.html. No new page and no new menu entry.
  • Answers sent through Podium counts by day, week or month (the existing By control) and by kind: permission, question, plan and message. The chart is the total per week; the table holds the kinds, with a footer row for each harness. The Harness filter narrows it, and every export carries a harness column.
  • How long sessions waited for an answer gives the median and the 90th percentile, overall, by kind and by week. A message has a dash, because it goes to a session that is not waiting.
  • The state toggle shows the one gap: answers and waits are recorded from the upgrade, so earlier weeks show a dash and the totals say which weeks they cover.
  • Both harnesses. A session of either one is answered through the same routes, so there is no gap to state. A figure that covers only answers sent from Podium says so in the line under each table.
  • Counts only, no person. Only the kind, the day, the harness and the wait are kept; never what was said. The tables are not by person, and there is no Person filter: #725 puts a per-person ranking out of scope. The Group filter is drawn because the Admin already filters by group elsewhere; the build can drop it if the stored rows cannot carry it.
  • No Admin read of content. Nothing here shows a person's text, so the "an Admin never reads in silence" notices do not apply.

What it needs underneath (not drawn)

  • The server already sees every answer (the respond routes) and when the ask was opened, so a new daily summary can hold, per day, harness and kind, the number of answers and the wait in time classes. It lands in every storage adapter in the same PR, with the 395-day retention the other summaries have.
  • Nothing changes in a reporter, so no harness needs a separate change.

Not new

  • Every class on the page exists already (.sum, .chart, .ptab, .seg, .apager, .note-line), and the chart is the same ink bars as Tools and Sessions. No color, component or pattern is added, so no standards fragment is needed.
