Podium settings window: /podium config

One command, the same settings in every harness. Each harness draws it with what its own interface allows, so the layout is the same where it can be, and the differences below are named, not hidden.

Issue #1001. Drawn from the spike's real captures of Claude Code 2.1.319 and OpenCode 2.2.5. A terminal frame uses Podium's tokens as a stand-in; the real colors are the person's terminal theme. The desktop apps were not checked and are tracked in #1122.

What every harness shows

The same four groups, in the same order, with the same words. A row says what it is, its value, and when a change takes effect.

GroupSettingsTakes effect
Consent (yours)Respond from Podium (respond), Message my other orchestrators (peers), Share the activity feed (activityFeed)Next start
ConnectionServer, your name. The token is never shown or set here.Next start
TimingReport interval, heartbeat, idle timeNext start
ContextWhich Podium context this session uses (list, use)Next start
A consent option is the person's own choice. A change is made only from this window, in the person's own session, and a project's files are never read for one. A setting that an environment variable already decides is marked set by PODIUM_RESPOND and cannot be changed here.

A harness with no window to open run in the spike

OpenCode started with opencode run has no terminal UI, and the command is not run there: the text goes to the model. Where the command does run with no UI, and in any harness that cannot host a page, it says where the settings are and takes the closest step the harness allows.

/podium config, no terminal UI

The settings window needs the terminal UI.
Your settings are in ~/.podium/config.env.
Edit it, or set the PODIUM_* variables.
They are read at the next start.

Claude Code with no pane (-p)

No settings window in this mode.
Run /plugin configure podium-reporter.

Wording not run for Claude Code.

Desktop and web apps not checked

The types suggest the Claude desktop app and VS Code can draw the same pane (Input and Select exist for them), and OpenCode's desktop and web apps have a separate GUI part. Nobody has run either. They are not drawn here; #1122 tracks the check, and a mockup follows if one can host the window.

Decided

  • Server and your name are read-only, with a pointer to /plugin configure podium-reporter in Claude Code. The token is never shown.
  • Claude Code focus: a keyboard route is tried first. If there is none, the limit is documented and /plugin configure stays the way in.
  • Every setting says "next start" in both harnesses until a reload is shown to apply a consent option live.
