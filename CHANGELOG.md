# Changelog

All notable changes to this project are documented in this file.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project follows [Semantic Versioning](https://semver.org/). Podium is
pre-1.0, so a minor release can include breaking changes.

Podium and its reporter mod, `podium-reporter`, share one version number, the way Kubernetes versions its
parts together. A release sets that number in every file `.claude/PROJECT.md` lists under "Releases", in the same
commit. Releases 0.2.0 to 0.14.3 were cut retroactively: each is the commit where the reporter's version
changed, and its section holds the changes that landed since the one before it. 0.14.3 also holds
the changes merged after the reporter's 0.14.3 bump, because it is the first release to carry both versions.

## [Unreleased]

### Added

- **A performance audit of `development`, with the scripts to repeat it (#682).** `docs/PERFORMANCE.md` records what the server, the console and the reporter cost at an idle, a small, a medium and a large fleet, and ranks fifteen findings, each filed as its own issue. `scripts/podium-perf.mjs` measures the server (CPU, memory, event-loop delay, stream bytes), `scripts/podium-perf-browser.sh` an open tab, and `scripts/podium-perf-mod.mjs` the reporter's own code. Each starts a throwaway server and stops it. No product code changed.

- **Podium contexts: switch between Podium servers the way `kubectl config use-context` does (#606).** A context is a name for one reporter config file (so one server and one person), kept in `~/.podium/contexts.json` with a current one. The reporter chooses `PODIUM_REPORTER_CONFIG`, then `PODIUM_REPORTER_CONTEXT` (one terminal), then the current context, then the newest file as before. `/podium context` and `podiumctl context` share the verbs `list`, `show`, `add <name> <file>`, `rename`, `remove` and `use`; `add` checks the file exists and is a reporter config. A running session keeps the context it started with, even across a plugin reload, and `use` says it applies from the next session, so two terminals can report to two servers at once. The status line shows `[name]` after the version and `/podium` shows `Context:`. A context that cannot be used shows `[context unusable]` in the status line and `Context problem:` in `/podium`, and the reporter uses the newest file. `podiumctl context` always writes `~/.podium/contexts.json`, where the reporter reads it. With no contexts nothing changes. SPEC 5.9, DECISIONS 46.

### Changed

- **`.claude/PROJECT.md` now says what and why, and the how moved into skills (#788).** The worktree steps, the PR checks and the trace check, the post-PR check watch, closing issues after a merge, the release sequence, the version-file table, hotfixes, the release check and the page-shot steps are in four new project skills (`podium-worktree`, `podium-pr-workflow`, `podium-release`, `podium-ui-verify`), and the doc-page rules joined `podium-docs-site`. `PROJECT.md` keeps the project's purpose, every Do Not and override, and a Skills table that names the skill to load for each action, so a session no longer carries the procedures it does not need.
- **The Files tab loads every changed file's diff in the background, so a diff opens with no wait (#631).** While the owner has a session's page open, the console asks for each file's diff, first-listed first and two at a time, and asks again when the file is edited again. The reporter marks each file with the git hash of its content (`rev`), so an edit that leaves the line counts alone is seen, and has a new `fileDiffPreload` option, on by default when `fileDiff` is on; set it to false to read a diff only when the file is opened. More of a session's source code leaves the machine, redacted, than before: a diff nobody opened is now read. The diffs live in the page's memory and are thrown away when the page is left; the server still keeps none. The admin log records a load as `file_diff_loaded` and an open as `file_diff_opened`. SPEC 6.4 and 7.7 now say "while the page is open" where they said "on request". The History page still shows no diffs for an archived session until they are stored (#632).
- **A gotcha for an Activity section that asks you to turn on `activityFeed` when it is on.** A session reads its reporter options once, when the plugin loads, so one that started before the option was turned on keeps saying it is off until `/reload-plugins` is run in it. Documentation only.
- **`.claude/CLAUDE.md` is now the standard baseline, and everything specific to Podium is in `.claude/PROJECT.md` (#772).** `CLAUDE.md` matches the baseline policy file used across projects, apart from naming `docs/architecture/` and `docs/spec/` where the baseline names single files, and it loads `PROJECT.md` with an `@PROJECT.md` import. `PROJECT.md` holds the overview, the Podium Do Nots, the worktree rule, the `Closes #N` override, the project skills, the UI standards, the release steps and the PR trace, atlas and release checks. The rules are unchanged; they moved. Docs and comments that cited a moved section now cite `PROJECT.md`.

- **The single-key shortcuts are off until you turn them on (#636).** `\`, `[`, `]` and `w` worked anywhere outside a text field and could not be switched off, so speech input or a stray key could collapse a pane or start wall mode (WCAG 2.1.4). They are now off by default. A **Shortcuts** switch in the bar under the top bar (beside Refresh every and Theme, and beside Theme on History) turns them on, and the choice is kept in that browser, so each browser needs it once. While it is off the hover tips and the Wall mode button's title no longer name their keys, and every button and `Esc` still work. If you use these keys today, turn Shortcuts on once.
  Standards: the Shortcuts field in the Display settings row (a `.field` holding the `.sw` switch, between Refresh every and Theme); approved with the mockup on #780 (`mockup/podium-shortcuts-off.html`, Option A, off by default).

### Fixed

- **At 400 px the top bar's edge tab no longer sits on the bar's last button (#787, from #636).** The tab is 24 px tall and reaches 12 px up into the bar, but the bar had 8 px of bottom padding, so on the wrapped second row it overlapped "Sign in" (or "History" when signed in) by 4 px and touched the line below. Below the 1040 px stacking width the bar now has 12 px of bottom padding. The bar at wide widths and the tab's size are unchanged.
  Standards: the top bar's bottom padding is 12 px below 1040 px, 8 px above; approved with the mockup on #787 (`mockup/podium-top-bar-edge-tab-gap.html`).
- **The reporter picks the newest config file by the epoch in its name, and reads only that file (#607).** Before, every session start read every `reporter-config-*.pem` in `~/.podium/` in full, private keys included, to compare their `issued-at` lines. Now the mod orders the names by their epoch and reads one file at a time, newest first, so the key of a file it does not choose is never read. SPEC 5.9 says "by the epoch in its name" where it said "by its `issued-at` header line"; a file renamed so the two disagree is ranked by its name.
- **The wall card's "Copy session id" is a real button beside the card, and big enough to hit (#759).** It was a `span role="button"` inside the card's own button, a control within a control that some screen readers skip or read oddly, about 19 px tall, and named "Copy session id 3f9a1c2e" while it read "Copied". It now sits next to the card's button, as the pin does, is at least 24 by 24 px, comes right after the card in the tab order, and is named by what it says. The card looks the same, but the path line is about 5 px taller.

- **Every page says where it is, to a screen reader (#636, the first part of the accessibility pass).** The page title now follows the route: "Podium board", "Podium traffic", "Podium my reporters", "<name> - Podium" for an open orchestrator and "Replay of <name> - Podium" for a replay (History and Admin already had theirs). The wall, the board and History each have one `h1` that is hidden from view and read by a screen reader ("Fleet", "Board", "History"); an open orchestrator and a replay keep their own. The row under the top bar that holds the refresh and theme controls is now a landmark named "Display settings", on Admin too. Nothing changes on screen.

- **Focus no longer falls to the top of the page after a sign-in (#636).** After you signed in from the top bar, or unlocked Admin, the form or button you used was replaced and keyboard focus dropped to the page, so the next Tab started again at the logo. Focus now moves to "Signed in as ..." in the top bar, or to the Admin page's heading. Neither draws a focus ring, since neither is a control.

- **The Agents tree's sort buttons are no longer announced as a table row with nothing around it (#636).** The header carried `role="row"` with no table, so a screen reader met a row that belonged to nothing, and the cells it held were plain boxes. The header is now a group named "Sort the agents". The agent rows below it were never table rows and are unchanged.

- **A control's name now holds the words it shows (#636).** Voice control and screen readers match on what is on the button, and several names did not contain it. The orchestrator page's Session cell is now "Session 3f9a1c2e, copy the full id", and its Resume and Fork cells read "Resume Command" and "Fork Command" as two words. A card on the board is named by its own text, so a step that shows its live wording ("Porting endpoints") is no longer named by its plain one, and a waiting card includes its reason; its state follows as one hidden word. A Traffic line's name starts with the same words as its pill, such as "1 message, waiting".

- **A password manager can fill the sign-in forms (#636).** The Admin unlock form and the Sign in dialog told the browser not to remember or fill the name and token (`autocomplete="off"`), so a person who keeps their token in a password manager had to type or paste it by hand each time (WCAG 3.3.8). The name is now `username` and the token `current-password`. The Admin secret is a token like any other, and Admin still locks after 10 minutes without activity.

- **Three pieces of text are easier to read in every theme but Solarized (#636).** The "need attention" count on the wall was amber on a light page (1.7:1 to 3.5:1 against the 4.5:1 WCAG asks for); it is now the amber mixed toward the ink. "no plan reported" on the selected rail row, and the "orchestrator" label on an agent row, were the muted grey on a highlight (3.8:1 to 4.5:1); both are now the secondary ink. No token changed. Solarized's own pairs (its secondary ink on its raised surface) are still just under 4.5:1 and wait for a decision about whether a theme may adjust its published colors.

- **Each Admin section says which one it is in the tab title (#636).** Every section kept the title "Podium admin", so a person with several tabs open, or a screen reader announcing the page, could not tell People from Settings (WCAG 2.4.2). Once Admin is open the title is now "Settings - Podium admin", "People - Podium admin" and so on, and follows the section as you move between them. The lock screen keeps "Podium admin".

- **The Activity panel's times and "go to" hints are readable on a gone row and on the selected row (#636).** A row whose session had gone was dimmed with `opacity`, which took its time and hint to 1.4:1 to 3.2:1 against the 4.5:1 WCAG asks for, and on the selected row the muted grey was 3.8:1 to 3.9:1 on its highlight in the default dark and Solarized themes. A gone row is now dimmed by the secondary ink instead of by opacity (a failed row keeps its own color), and the selected row's time and hint use the secondary ink. No token changed. The selected row in Solarized is still just under 4.5:1 (4.47:1 light, 3.85:1 dark) and waits with the rest of Solarized.

- **The "Notice turned off" confirmation waits while you are reading it (#636).** It cleared itself after 9 seconds whatever you were doing, and it holds the link to Admin > Settings, so someone moving slowly, or reaching it by keyboard, could lose it before they got there (WCAG 2.2.1). It now stays while the pointer is over it or focus is inside it, and the 9 seconds start again once both have left. The wait, the look and the X are unchanged.

- **The edge tab is big enough to hit (#636).** The collapse control on the top bar, the Kanban KPI rows, both side panes and the Plan / Files fold was 16 px on its short side, under the 24 px WCAG 2.5.8 asks for. It is now 32 x 24 on a horizontal edge and 24 x 32 on a vertical one, wherever it appears. It straddles its edge 12 px instead of 8, so at 400 px, where the top bar wraps, the top tab overlaps the bottom few pixels of the bar's last button; the button stays reachable.
  Standards: the edge tab (`.edge-tab`) is 32 x 24 on a horizontal edge and 24 x 32 on a vertical one, up from 32 x 16 and 16 x 32 (#626), and straddles 12 px instead of 8; approved with the mockup on #779 (`mockup/podium-edge-tab-target-size.html`, Option A).

- **A permission prompt reaches the card on a Team or Enterprise login, and the console says sooner that it cannot be answered from Podium (#742).** Claude Code's guard `cc-plugin-sec-default` skips the mod's `classic.PermissionRequest` there, so the prompt never showed. The reporter now records it from `tool.check` resolving `ask` (waiting on a permission, with the tool and its input) once, even if the hook arrives late, and a session whose turn ended with no classic hook having run is marked as one that cannot be answered before its first prompt, not only after it. A `tool.check` hook cannot answer for the person, so answering stays in the terminal; plan feedback and questions still work. See SPEC 5.3 and the gotcha. Reporter only; the console and the server do not change.

- **A session waiting on a permission prompt shows as waiting on a Team or Enterprise login, even with responding off, and no longer stays waiting when the prompt was answered within two seconds (#741).** Claude Code skips `classic.Notification` there. The wait now comes from the same `tool.check` fallback, which no longer depends on the responding option. Other notification types have no other source and were never used. Reporter only.

- **Documented: the card cannot show a session's background tasks and scheduled wake-ups on a Team or Enterprise login (#740).** The engine offers no call that lists them apart from the `classic.Stop` hook the guard skips, so a session idle on background work reads as waiting for you. A test pins what the card shows. See the gotcha and `docs/REPORTER.md`.

- **A session in the Claude desktop app is named after the title the app shows for it (#595).** Every desktop session in one folder showed that folder's name, because the app's titles never reached the `session_title` the reporter reads from the `classic.SessionStart` and `classic.UserPromptSubmit` hooks. On a Team or Enterprise login, or a machine with managed settings, Claude Code's own guard skips every `classic.*` hook of a user-installed mod, so no title ever arrives. The reporter now also reads the `name` of the session's entry in `claude agents --json` on the first git poll and about every 30 seconds after, and uses it when no hook has given a title; a hook's title and `/podium name` still win (SPEC 6.6). The same skip also stops the other `classic.*` hooks, so on those logins background tasks and crons (`classic.Stop`), notification signals and answering permission prompts from Podium are still not reported; the gotcha "My session's name is the folder, and background tasks, notifications and permission answers are missing" says so.

- **A failed TLS handshake on the reporter port says why and where from, and a symlink can no longer redirect the reporter's config write (#672).** The server log named only `socket hang up`; it now gives Node's error code and the short OpenSSL reason (`ERR_SSL_PEER_DID_NOT_RETURN_A_CERTIFICATE: peer did not return a certificate`), words repeats alike so the text log folds them, and keeps the source address as a field. The reporter helper creates its temporary file with `wx`, and rewrites a config file that is a symlink at the file it points to, so the link stays a link. A refused client certificate that reads as a reset is written up in the gotchas. A 403 from the connection helper (`ROUTE_NOT_ALLOWED`) is no longer retried every few seconds like an outage; a 403 from the server is handled as before. `config unreadable` on the status line now carries the reason, such as a config holding more than one person certificate. Pressing Escape on the People confirmation row now closes it, and Escape or Cancel on it and on the Rotate CA and Retire old CA confirmations returns focus to the button that opened them.

- **A session the Claude desktop app keeps open no longer leaves the wall because another session is on screen (#594).** The desktop app attaches a client only to the session in view, so every other open session read as "nobody attached" and left the wall a minute later behind "background sessions hidden". The reporter now counts a session as attached once a desktop client has been on it, until it ends. Deleting a session from the app's sidebar ends it, and its card leaves the wall as before; a terminal session with nobody on it is still a background session.

- **Four tests that timed out at 5,000 ms on CI runners no longer do (#680, #681).** The activity history "compact in steps" test ran about 175 one-step vacuums on a file database, so a slow disk took it past the limit; it now runs a dozen steps over a smaller file and still crosses several delete chunks. The side, history and Admin delete-people tests render a large tree and are slow under coverage, so each has a 30 s limit that matches the work. No test code outside those four tests and no production code changed.

### Changed

- **`npm test` now runs an accessibility check on the console's pages and the published standards pages (#636).** `frontend/src/fleet/a11y.axe.test.tsx` runs axe-core over the wall, an orchestrator's page, the board, Traffic, My reporters, History, the Admin lock screen and every standards page but `components.html`, and fails on any violation that is not listed as known with its reason. jsdom has no layout, so contrast and target size are left to the manual pass.

- **The server prints the reporter port and the CA backup reminder at startup, and the "renewal due" badge follows the reporter's rule (#672).** `podium: made a CA in …; back the folder up` and `Podium HTTPS listening on … for reporters (CA …, expires …)` print at the default log level, so `podiumctl run` and `npm start` say where reporters connect. A person's certificate shows *renewal due* when 30 days or half its lifetime remain, whichever is shorter, as the reporter renews it; the Admin People list carries the certificate's start date for that, and the lifetime hint in Admin > Settings says the same. Documentation: a gotcha for the reset a refused certificate causes, decision 42 words what stays on plain HTTP, and MESSAGING.md says messaging works over a certificate.

- **The docs say what happens to Claude desktop app sessions after the app restarts (#737).** The app restores only the session on screen and leaves the others dormant, and the reporter runs inside each session, so nothing reports for a dormant session. SPEC 7.5, the user guide and the desktop gotcha now state that the on-screen session is revived under its old id, the others return when opened (possibly under a new id), and Podium keeps no card for a session that is not reporting. The lifecycle timers do not change. Documentation only.
- **A blowout event records the context window and how full it was (#735).** A usage reset showed as a blowout on a card whose context bar read 25% (#687), and the event sequence at a reset could not be told from a real overflow. The reporter's `blow` event now carries `window` and `percent` beside the kind and the tokens before and after, for a window-exceeded stop, a server compaction and an automatic compaction. Nothing is counted differently yet: the fix that stops a reset counting waits for the next one to show which path fires. Reporter only; the console and the server do not change.

### Fixed

- **The TLS tests no longer fail intermittently when the listener cannot start (#670).** Five test files chose a port ahead of binding it, and when `startTls` returned null the test failed on a `TypeError` two lines later (it failed twice in a row on a CI run of #728). They now start the listener through one helper, `startTlsForTest` in `server/src/tlsTesting.ts`, which retries on another port when the port was taken and otherwise fails with the reason `startTls` logged. Test-only: the server is unchanged.

- **`npm run test:mod` passes again with Claude Code 2.1.310 (#718).** 33 of its tests failed on a clean `development` and on `v1.3.0`: the test engine now denies a faked `ask` permission check, and two tests still expected version 1.2.2. The tests answer `allow` unless one needs an `ask`, and read the version from the mod. Test-only: the mod and the server are unchanged.

- **One machine shows one name, however the network names it (#715).** The mod read the machine's name with `hostname`, which on a Mac with no `HostName` set follows the network (a session could say `Mac`, another `Dana-MacBook-Pro`) and on Linux changes with a DHCP hostname or a recreated container. The mod now reads `scutil --get LocalHostName` on macOS, falls back to `hostname`, and keeps the first name it reads in `podium-machine-name` next to `podium-machine-id`, so every later session reports it. Delete that file to take the machine's current name. SPEC 6.2, decision 21, the reporter guide and the user guide say so.

- **Seven passages of the spec say what they mean (#705).** The heading in SPEC 5.9 now reads "Notes on six options"; the sentence in 7.7 that stopped at "The reporter's side is" and the one in 8.1 that had no verb are complete; the wall-notices list in 8.1 no longer contradicts itself about which notice is in `NOTICES`; "the new use" in 7.7 is "the new fields"; a comma is added in 6.4; and the build-time branch instruction in 10.1 is now the current rule. No numbered heading changed and no behavior described. Documentation only.

- **The Actions menu samples on the standards Components page will sit in the page (#700).** The row Actions menu (`.menubox`) is `position: fixed` in the app, and the standards draw it that way, so its 25 samples float over the page and cover its navigation. A new check in the standards parity pass fails when any `position: fixed` class in `fleet.css` or `admin.css` has no in-place rule for samples in `docs/standards/standards.css`, so the next fixed part is caught when it is added. It fails for `.menubox` until the fix reaches the standards pages with the next release. Standards: add `.menubox` to the selector in `docs/standards/standards.css` that reads `.s-sample .toast, .s-sample .tipbox { position: static; }`, so it draws the Actions menu samples in place; approved by the maintainer when asked to fix #700 on 2026-10-25.

- **The nightly build publishes again (#698).** The `Nightly` workflow failed on every scheduled run because the generic self-hosted runners have no GitHub CLI, so `gh` was not found and no `nightly-YYYY-MM-DD` prerelease was ever made. Each job now installs a pinned `gh` (no `sudo`, checked against the release's checksums) unless the runner already has one. The "already has a nightly" check also no longer swallows a failing `gh`, which had made it always report that a nightly was needed.

- **A person's certificate can be renewed once an hour (#612, part of #577).** `POST /api/reporter/renew` answers `429` with `Retry-After` and the code `TOO_SOON` while the person's newest live certificate was issued less than an hour ago, before it starts `openssl` or adds a row, so a looping or hostile client holding a valid certificate cannot fill `person_certificates` or keep the server busy. The limit is fixed at an hour, not a setting. The helper treats a `429` as a wait, not a refusal: the request still goes out, the file is left alone, and it asks again after the `Retry-After` time (never sooner than a minute). A refused renewal is logged as `tls.reporter_renew_refused` with the code.

- **The reporter renews its own certificate, and the server checks the grace (#585, part of #577).** A person's certificate lasts `tls.reporter.lifetimeDays` (90; 30 to 365) and the helper renews it when 30 days of it are left, at start, before a request, and every 10 minutes while a session idles. It makes a new EC P-256 key and sends only the public key to the new `POST /api/reporter/renew`, which is answered to a client certificate and nothing else. The server signs that key for the same person and returns the certificate and the CA(s). The helper checks the answer (our key, signed by a CA the file already holds), then rewrites the config file in one rename at mode 0600 under a lock file (`<file>.lock`, taken over after a minute if its owner died), so several sessions renewing at once leave one valid file and the second takes the first's certificate. The old certificate stays live until it expires, and each is its own row. An expired certificate may still renew for `tls.reporter.graceDays` (30; 0 to 90) after it expired, and the status line says it is renewing. The server never trusts `CERT_HAS_EXPIRED` or a serial for that: the certificate's bytes must equal the stored one and its signature must verify under the CA key that issued it (`X509Certificate.verify`), so an expired forgery with the same subject and serial, from a fake CA or self-signed, is refused. Past the grace, or for a revoked certificate, the status line and `/podium` say to ask an Admin to reissue the config. Both settings can be saved with `PUT /api/admin/certificates` (the page that shows them is T8, #586). A CA arriving in the renewal response is T10 (#588); this step never adds a CA the file does not already hold. `PODIUM_RENEW_BEFORE_SECONDS` and `PODIUM_RENEW_CHECK_SECONDS` change the helper's thresholds for tests.

- **The reporter connects over TLS with the person's certificate (#584, part of #577).** When a reporter config file exists (`PODIUM_REPORTER_CONFIG`, or the newest `reporter-config-*.pem` in `~/.podium/` by its issued-at line), the mod starts a small Node helper, `hooks/helper.mjs`, once per session and sends its requests to it over a Unix socket with `$.http.fetch(..., { socketPath })`. The helper makes the HTTPS connection with the CA and the person's certificate from the file, so nothing is installed and `NODE_EXTRA_CA_CERTS` is not used. The server address and the name come from the file. It forces certificate verification on, clears `NODE_TLS_REJECT_UNAUTHORIZED` and `NODE_OPTIONS`, keeps one socket per session in a 0700 folder with mode 0600, prints `ready` when it listens, exits when its parent dies and removes only its own socket, reports a failure in an `X-Podium-Helper-Error` header, and aborts the response on an upstream error mid-body. It refuses a config file that group or others can read. It re-reads the same file only for the same person and keeps the last good copy when a read fails. A `/clear` does not stop it. The reporter finds `node` by `PODIUM_NODE`, then its PATH, then the usual places (Homebrew, `/usr/local`, nvm, Volta); a missing `node`, a loose file mode, a file for another name, an expired certificate, a revoked one, or a server certificate that is expired, for another name or signed by another CA each show in the status line and in `/podium` instead of a bare "offline". - **Sessions renewing together can no longer both get the renewal lock (#611, #616, part of #577).** A reporter's renewal lock is now a numbered file, `<config>.lock.<n>`, made with O_EXCL and naming its owner. It is held by the highest number and free when there is none or the highest is older than a minute (its owner died, or let go: a finished session ages its file instead of removing it, so a number is never used twice). To take it a session creates the next number, and of several that want the same number exactly one succeeds, so taking over a stale lock removes nothing that two sessions could race on, one can never delete a lock another has just made, and one working from an old reading cannot be handed a number that was held and released since. ## [0.8.0] - 2026-10-12

### Added

- An Admin section where the server owner makes a token for each person, bound to that person's name. Open it from the new Admin button in the top bar's upper right (`#/admin`) and enter the admin secret, which is the `PODIUM_TOKEN` that `podiumctl token` prints. Admin has four tabs, People, Groups, Reporting and security and Admin log, and every list is paged by the server (50 rows by default, at most 100) with a search over name, group and machine. A token (`pdm_<key id>_<secret>`, 192 bits of randomness) is shown once with the settings to paste, then only its last four characters; the database keeps a SHA-256, never the token. A report is accepted only when its token is live and the `userName` it sends is that token's person, so a valid token with another person's name, an unknown name, a revoked token or a token rotated away is refused with a 401. The server decides who a session belongs to from the token and stores it in `sessions.owner`; the shared `PODIUM_TOKEN` keeps working for reporting (owner `Admin`, with a switch in Admin to turn that off), so an existing setup is unchanged. Groups are labels for arranging people, one per person, and deleting a group moves its people to "No group". Admin locks after 10 idle minutes, five wrong secrets lock a source address for 15 minutes, every change needs an `X-Podium-Admin` header and the server's own origin, responses are `no-store`, and unlocks, failed unlocks, changes and their source addresses go in the admin log; no token or secret is logged, returned again or kept in browser storage. Without a `PODIUM_TOKEN` Admin is off. This adds a database migration (version 6: `people`, `groups`, `person_machines`, `admin_log`, `settings` and `sessions.owner`), `userName` on the report and `owner` on a session, a `userName` mod option, and moves the mod to 0.8.0 and the supported reporter range to 0.2.0–0.8.0. The mod now treats a 401 as a refused credential: it keeps its events, logs it once, shows `podium ○ token refused` and tries again about once a minute, where it used to retry with a short backoff and say nothing. Tokens still travel over plain HTTP, so a server reachable over a network needs a trusted network or a TLS proxy. (#36)

## [0.1.0] - 2026-10-11

First release. The repo started as a usage dashboard and became Podium, a live
fleet console for Claude Code sessions, with a container, a command-line manager
and a plugin you can install from a marketplace.

### Added

- **Podium fleet console** (`#/`, the default view). Every Claude Code session
  running with the reporter mod shows up in one browser tab within about two
  seconds: model and effort, plan, the agents it launched (subagents and forks),
  estimated cost, context-window fill, context blowouts, failures with the
  failing call and its last output, and the git branch or worktree. Sessions
  appear and leave on their own. Podium only observes; it never sends a prompt or
  touches a session. (PR #2)
- **Reporter mod** (`mod/podium-reporter/`): a Claude Code mod that reports a
  full snapshot plus unacknowledged events, redacts anything that looks like a
  secret, queues reports while the server is down, and adds the `/podium`
  command and a status line entry. Options: `serverUrl`, `token`,
  `flushIntervalMs`, `heartbeatMs`, `sessionName`, `showStatus`,
  `explainFailures`. (PR #2)
- **Server** (`server/src/fleet/`): hand-written validation of every report,
  SQLite storage through `node:sqlite`, Server-Sent Events for live updates,
  stale and drop timers, retention, and a `/history` endpoint. A shared token
  (`PODIUM_TOKEN`) guards reports, hooks and deletes. (PR #2)
- **Settings-hook ingest** (`POST /api/fleet/hook`): a reduced view of sessions
  started without the mod, from Claude Code's settings hooks. (PR #2)
- **History page** (`#/history`) listing the sessions that ended on a chosen
  day. (PR #2)
- **Simulator, smoke and soak scripts** (`scripts/podium-sim.ts`,
  `podium-smoke.sh`, `podium-soak.sh`) for developing and checking Podium with no
  real sessions. (PR #2)
- **`podiumctl`** (`bin/podiumctl.mjs`): start, stop, restart, status, logs,
  health, token, config, enable and disable (start on boot through launchd or a
  systemd user unit), shell and rm, in either a Podman container or a standalone
  Node process. The first start generates an auth token and saves it to
  `~/.podium/config.env`. (PR #3)
- **Container image** (`Containerfile`): a two-stage Node 24 build that runs as
  a non-root user and keeps its database in a `/data` volume. (PR #3)
- **Marketplace install.** `podium-reporter` is listed in
  `eengelking-marketplace` (`eengelking/skills`):
  `/plugin install podium-reporter@eengelking-marketplace`. (`eengelking/skills`
  PRs #32 and #33)
- **Docs:** `docs/SPEC.md`, `docs/ARCHITECTURE.md`, `docs/DEMO.md`,
  `docs/DECISIONS.md`, `docs/GOTCHAS.md`, `docs/USER_GUIDE.md`, `CONTRIBUTING.md`
  and the `.github/` community files, issue and PR templates, and CI.
  (PRs #1, #4, #6 and this release)
- **Usage dashboard** (`#/usage`, the earlier app): charts Claude Code and
  Anthropic Admin API usage from local logs and the Admin API.

### Changed

- The project was renamed from `claude-dashboard` to `podium`
  (`eengelking/podium`). (PR #5)
