**A PR adds a changelog fragment instead of editing `CHANGELOG.md` (DECISIONS 67).** Every PR used to add its line to the same few lines of `[Unreleased]`, so each merge sent the other open PRs back through CI with a conflict. A PR now adds `changelog.d/<issue-or-slug>.<type>.md` (`added`, `changed`, `deprecated`, `removed`, `fixed` or `standards`), and the `release-prep/<version>` PR runs the new `scripts/changelog-assemble.mjs` to append the fragments to `[Unreleased]` and delete them. `npm test` fails on a fragment with a bad name, type or text. Entries already under `[Unreleased]` stay as they are. The PR template, CONTRIBUTING, `docs/PATTERNS.md`, `.claude/PROJECT.md` and the release, atlas and standards skills say the same.
