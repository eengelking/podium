Chat and Direct Message data is stored once, and a message is saved faster, with nothing lost: a delivery no longer repeats its conversation, an Admin record's owed rows are found by the person's id alone, and the list of who had seen a record is gone. Every Admin read still tells the person, in the console and in `podium-reporter`, and the Admin log is unchanged. Saving a message no longer scans a table to number it, and a person's Direct Messages are found by an index. SQLite also keeps four tables (deliveries, owed rows, read counts and the Activity history's loop totals) in one place instead of two, which makes the deliveries table 59% smaller. The database upgrades on its own (SQLite migrations 56 to 58 and a few more, PostgreSQL and MariaDB steps 32 to 34 and more); an upgrade of a SQLite file can grow it until the next `VACUUM` (#1296)
