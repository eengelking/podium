The container health check and `podiumctl`'s own health check (`podiumctl health`, `status` and the wait at start) now call `GET /api/health` instead of `GET /api/fleet/state`. The state route builds every session's view: at 50 sessions with 20 agents each it returns 1.28 MB and takes about 13 ms (4 ms and 372 KB at 20 sessions), against 15 bytes and under 1 ms for `/api/health`. At the large fleet the container check alone moved about 3.7 GB a day over loopback and spent about 40 seconds of server CPU a day, plus a new Node process each time. The check now answers "does the server respond", not "can the fleet build its state" (#767).
