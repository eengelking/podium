The console does less work when an open conversation of people and agents changes, and when one action changes several parts of Chat. A conversation is read, kept and drawn the way a channel or Direct Message is: it lands with the overview in one draw, a message that did not change is not parsed or drawn again (a read of a conversation of 50 messages used to parse all 50 three times), and it reads the earlier pages you loaded again, one request for each. The stream sends one `chat` event for each part of Chat an action changed, and the console now counts the events that arrive within one frame (16 ms) as one, so an action that changed several parts is read once and not once for each. Nothing waits longer than a frame, and a snapshot, the other stream events and the page's other reads are as they were (#1296).
